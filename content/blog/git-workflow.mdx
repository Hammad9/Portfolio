Git is simple until it is not. A clear workflow prevents conflicts, confusion, and production incidents.

## Branching Strategy

Use trunk-based development or GitFlow depending on your release cadence. For most modern teams, a main branch with short-lived feature branches is enough.

## Commit Conventions

Write commits as actions: "Add user authentication", "Fix navigation overlap on mobile". Conventional Commits make changelogs and versioning automatic.

## Pull Requests

Keep pull requests small and focused. Large PRs are harder to review and more likely to introduce bugs. Require at least one review before merging.

## Continuous Integration

Run linting, type checking, and tests on every pull request. CI is your safety net.

## Deployment

Automate deployments from main to staging. Promote verified builds to production. Rollback should be one click away.

A good Git workflow is invisible. It lets the team focus on shipping value instead of resolving conflicts.
